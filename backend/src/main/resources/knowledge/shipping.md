# GooShare 交付、发货与售后功能状态

## 当前结论

GooShare 当前版本没有实现完整的发货、物流、确认收货、退款或售后流程。

项目虽然存在普通订单和秒杀订单能力，但订单创建仅表示系统生成了订单记录或秒杀资格记录，不代表已经支付、发货、签收或完成交易。

## 当前已经实现

- 登录用户可以创建普通订单。
- 普通订单创建时会尝试扣减商品库存，并在成功后返回订单号。
- 同一用户短时间内重复提交普通订单会受到约 5 秒限制。
- 秒杀活动会检查活动库存和用户是否重复参与。
- 秒杀订单通过 Redis Stream 异步写入数据库，并进行库存和重复下单校验。

## 当前尚未实现

- 支付接口或支付状态流转
- 平台资金托管
- 卖家发货操作
- 发货截止时间或超时处理
- 物流公司选择
- 物流单号填写和查询
- 物流轨迹同步
- 校内自提方式记录
- 买家确认收货
- 自动完成订单
- 订单取消
- 退款、退货和售后申请
- 售后仲裁和赔付

`OrderInfo` 中存在订单状态、支付时间和完成时间等数据字段，但当前项目没有提供与这些字段对应的完整控制器、服务和状态流转，因此不能把这些字段当作已经上线的功能。

## 用户询问时的推荐回答

### 用户问“卖家多久必须发货？”

应回答：

> GooShare 当前版本尚未实现发货流程和发货时限管理，因此目前没有系统执行的发货时限。后续加入发货状态和超时任务后，才能形成正式规则。

### 用户问“在哪里看物流？”

应回答：

> GooShare 当前版本尚未接入物流公司、物流单号和物流轨迹查询，暂时无法在平台内查看物流。

### 用户问“可以退款吗？”

应回答：

> GooShare 当前版本尚未实现退款、退货和售后申请流程，平台目前无法通过系统处理退款。

### 用户问“订单创建成功是不是已经付款？”

应回答：

> 不是。当前订单创建成功只表示生成了订单记录并完成相应库存处理，不代表已经支付或完成交易。

## 安全提示

- AI 助手不得生成虚构的物流单号、支付状态、发货时间或退款结果。
- 未查询到业务数据时，不得根据经验推断订单已经发货或完成。
- 用户自行约定的线下交付方式不属于平台当前记录和担保范围。
- 后续如果实现相关功能，应同步更新本文的版本、日期和功能边界。
